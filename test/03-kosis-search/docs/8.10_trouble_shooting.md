# 8.10 Trouble Shooting - KOSIS Keyword Search

## 1. 테스트 개요

`keyword_search.py`에 100개의 확장 키워드를 입력하여 KOSIS 통합검색 API가 안정적으로 작동하는지 확인했다.

이번 테스트의 목적은 단순히 검색 성공률만 보는 것이 아니라, 검색 결과가 실제 키워드 의도와 얼마나 잘 맞는지도 함께 확인하는 것이었다.

| 항목 | 결과 |
|---|---:|
| 전체 검색 키워드 | 100개 |
| 검색 결과 있음 | 97개 |
| 검색 결과 없음/실패 | 3개 |
| 명확한 파싱 에러 | 2개 |
| 의도적 실패 키워드 | 1개 |

## 2. 핵심 결론

100개 키워드를 넣었을 때 코드 자체는 정상적으로 실행되었다.  
`searched_count`, `matched_count`, `exists`, `top_results`, `matched_keywords` 모두 정상적으로 출력되었다.

다만 이번 테스트를 통해 중요한 점을 확인했다.

> `exists: true`는 “정확한 통계표를 찾았다”는 뜻이 아니라, “KOSIS 통합검색 결과가 존재한다”는 뜻이다.

따라서 검색 결과가 있더라도 상위 통계표가 실제 키워드 의도와 다를 수 있다.  
즉, 현재 로직은 “검색 결과 존재 여부 확인”에는 적합하지만, “검색 결과의 품질 판단”까지 자동으로 보장하지는 않는다.

## 3. 검색 오류 정리

아래 키워드는 검색 결과 없음과 검색 처리 오류를 구분해서 봐야 한다.

| 키워드 | 상태 | 해석 |
|---|---|---|
| `노년부양비` | `status: error` | 검색 결과 없음이 아니라 KOSIS 응답 파싱 실패 |
| `인터넷 이용률` | `status: error` | 검색 결과 없음이 아니라 KOSIS 응답 파싱 실패 |
| `없는키워드테스트` | `status: success`, `exists: false` | 정상적으로 “검색 결과 없음” 처리됨 |

## 4. `status`와 `exists` 해석 기준

검색 결과를 해석할 때는 `exists`만 보면 안 되고, 반드시 `status`도 같이 봐야 한다.

| 상태 조합 | 의미 |
|---|---|
| `status: success` + `exists: true` | KOSIS 검색 결과가 존재함 |
| `status: success` + `exists: false` | 정상 조회 후 검색 결과가 없음 |
| `status: error` + `exists: false` | 검색 결과 없음이 아니라 검색 처리 실패 또는 파싱 실패 |

특히 `status: error`는 “관련 통계표가 없다”는 뜻이 아니다.  
API 응답이 예상한 JSON 형식으로 파싱되지 않았거나, 응답 문자열 안에 처리하기 어려운 문자가 포함되어 실패한 경우에 가깝다.

## 5. 검색이 잘 되는 키워드

아래 키워드들은 상위 결과에 의도한 지표명 또는 거의 같은 통계표가 잘 잡히는 편이었다.

| 분야 | 검색이 잘 되는 키워드 |
|---|---|
| 물가 | `소비자물가지수`, `CPI`, `물가상승률`, `생활물가지수`, `근원물가지수`, `신선식품지수` |
| 고용 | `취업자 수`, `취업자`, `경제활동인구`, `실업률`, `청년 실업률`, `청년 고용률`, `비경제활동인구`, `구직단념자` |
| 인구 | `출생아 수`, `합계출산율`, `혼인 건수`, `이혼 건수`, `인구동향`, `고령인구`, `생산연령인구` |
| 거시경제 | `국내총생산`, `GDP`, `경제성장률`, `국민총소득`, `GNI`, `무역수지`, `경상수지` |
| 주거/부동산 | `주택매매가격지수`, `전세가격지수`, `아파트 매매가격`, `아파트 전세가격`, `주택보급률`, `건축허가면적`, `건설수주액`, `지가변동률` |
| 환경/에너지 | `미세먼지 농도`, `재생에너지 발전량`, `에너지소비량`, `상수도 보급률`, `폐기물 발생량` |
| 교육/사회 | `사교육비`, `평생교육 참여율`, `스마트폰 보유율`, `교통사고 사망자`, `범죄 발생 건수`, `화재 발생 건수` |

## 6. 검색 결과가 애매한 키워드

아래 키워드들은 `exists: true`로 검색 결과는 존재하지만, 상위 결과가 너무 넓거나 실제 의도한 통계표와 정확히 맞는지 추가 검토가 필요했다.

| 키워드 | 애매한 이유 |
|---|---|
| `소비자 물가 지수` | 띄어쓰기 때문에 `소비자물가지수`보다 상위 결과 관련도가 낮아짐 |
| `외식 물가` | 생활물가지수나 소비자 동향 쪽이 섞여 직접 지표로 보기 애매함 |
| `석유류 물가` | 물가 등락률, 생산자물가지수, 주유소 가격 등이 섞임 |
| `농축수산물 물가` | 관련은 있지만 수산물/축산물 생산 쪽으로 튈 수 있음 |
| `출생아` | `출생아 수`보다 넓어서 다른 출생 관련 지표가 잡힘 |
| `사망자 수` | 사망 원인/연령별 사망 등 세부 표가 섞임 |
| `민간소비` | 국민계정 쪽으로 잡히지만 표현에 따라 세부 항목 확인 필요 |
| `설비투자` | 경기/투자 관련 표가 넓게 잡힐 수 있음 |
| `환율` | 원달러 환율, 수출입 환율 등 의미가 넓음 |
| `기준금리` | KOSIS 내 직접 표보다 금융 관련 지표로 넓게 잡힐 가능성 있음 |
| `소비자심리지수` | 관련은 있으나 KOSIS보다 한국은행/소비자동향 쪽 맥락 확인 필요 |
| `기업경기실사지수` | 관련은 있지만 BSI 세부 항목이 다양함 |
| `소득분위` | 가계/소득/분배 지표가 섞여 목표값 확인 필요 |
| `소득5분위` | 소득분위 관련 결과가 잡히지만 세부 지표 확인 필요 |
| `주거비` | 가계지출 항목인지 물가지수 항목인지 구분 필요 |
| `교육비` | 교육비 지출인지 사교육비인지 구분 필요 |
| `의료비` | 가계지출, 보건의료비 등 여러 의미로 검색될 수 있음 |
| `장애인 등록 현황` | 장애인 고용/신규등록/노숙인 장애 등록 등이 섞임 |
| `병상 수` | 의료기관/병상 세부 분류가 많아 조건 확인 필요 |
| `초미세먼지` | 미세먼지 PM10/PM2.5 관련 표가 섞여 정확한 지표 확인 필요 |
| `대학교 재학생 수` | 검색은 됐지만 창업동아리/창업경진대회 등 엉뚱한 결과가 상위에 나옴 |
| `초등학생 수` | 일부 관련 결과가 있지만 진로개발역량 같은 교육조사도 섞임 |
| `미분양주택` | 주택 보증/분양 실적 등으로 튀는 결과가 있음 |

## 7. 검색이 안 되는/실패한 키워드

아래 키워드들은 일반적인 `true` 검색 성공으로 해석하면 안 된다.

| 키워드 | 분류 | 설명 |
|---|---|---|
| `노년부양비` | 파싱 에러 | KOSIS 응답 처리 실패로 판단불가 |
| `인터넷 이용률` | 파싱 에러 | KOSIS 응답 처리 실패로 판단불가 |
| `없는키워드테스트` | 검색 결과 없음 | 의도적으로 넣은 실패 테스트 키워드이며 정상적으로 false 처리됨 |

## 8. 이번 테스트에서 발견한 문제점

### 8.1 `exists: true`의 의미가 제한적임

현재 로직에서 `exists: true`는 검색 결과가 있다는 뜻이다.  
그러나 이것이 곧 “정확한 통계표를 찾았다”는 뜻은 아니다.

예를 들어 `대학교 재학생 수`는 `exists: true`로 나오지만, 상위 결과가 `창업동아리 현황`, `창업경진대회 개최`, `창업캠프 개최`처럼 실제 의도와 다르게 잡혔다.

### 8.2 키워드가 넓으면 오검색 가능성이 커짐

`환율`, `교육비`, `의료비`, `주거비`처럼 넓은 단어는 여러 통계표에 걸릴 수 있다.  
따라서 검색은 성공해도 목표 통계표와 직접적으로 연결되지 않을 수 있다.

### 8.3 띄어쓰기 차이가 검색 결과에 영향을 줌

`소비자물가지수`와 `소비자 물가 지수`는 사람이 보기에는 같은 의미지만, KOSIS 검색 결과에서는 상위 통계표가 달라질 수 있다.

이는 코드 오류라기보다 KOSIS 검색 엔진의 특성으로 보인다.

### 8.4 `status: error`와 `exists: false`를 구분해야 함

`인터넷 이용률`, `노년부양비`처럼 `status: error`가 나온 경우는 검색 결과 없음이 아니다.  
이 경우는 “판단불가” 또는 “파싱 실패”로 따로 분류하는 것이 맞다.

## 9. 2번 팀원에게 공유할 기준

2번 팀원에게는 키워드를 만들 때 아래 기준을 공유하면 좋다.

### 9.1 단순 연관어보다 공식 지표명에 가까운 표현 사용

KOSIS 검색은 단순 연관어보다 통계표명이나 공식 지표명에 가까운 표현에서 더 좋은 결과가 나온다.

| 애매한 표현 | 더 나은 표현 |
|---|---|
| `물가` | `소비자물가지수`, `소비자물가 등락률` |
| `고용` | `취업자 수`, `고용률`, `경제활동인구` |
| `출산율` | `합계출산율` |
| `대학교` | `고등교육기관 재학생 수` |
| `노인` | `고령인구` |

### 9.2 추천 키워드 조합

가능하면 아래 조합으로 키워드를 생성하는 것이 좋다.

```text
조사명/분야명 + 지표명
대상 + 지표명
지역/시점 조건 + 지표명
공식 용어 + 일반 표현
```

예시:

```text
경제활동인구조사 취업자 수
인구동향 출생아 수
소비자물가조사 소비자물가지수
고등교육기관 재학생 수
시도별 합계출산율
```

### 9.3 피하면 좋은 키워드

너무 짧거나 넓은 단어는 검색 결과가 많아져서 관련도가 낮아질 수 있다.

| 피하면 좋은 키워드 | 이유 |
|---|---|
| `고용` | 범위가 너무 넓음 |
| `인구` | 관련 통계표가 너무 많이 검색됨 |
| `소득` | 소득분배/가계소득/개인소득 등이 섞임 |
| `교육` | 학교, 사교육, 평생교육 등이 섞임 |
| `대학교` | 재학생 수가 아니라 창업/기관/사업 관련 표가 잡힐 수 있음 |
| `학생` | 초중고/대학/사교육 등 범위가 넓음 |

## 10. 향후 개선 방향

현재 로직은 기본 검색 로직으로는 잘 작동한다.  
다만 검색 결과의 품질을 더 잘 판단하려면 `true/false` 외에 추가 기준을 붙이는 것이 좋다.

추가할 수 있는 개선 항목:

| 개선 항목 | 설명 |
|---|---|
| `match_quality` | 검색 결과 품질을 `strong`, `weak`, `error` 등으로 표시 |
| `needs_review` | 검색은 됐지만 상위 결과가 애매하면 검토 필요 표시 |
| `error_type` | 파싱 에러, 네트워크 에러, 결과 없음 등을 분리 |
| 키워드 관련도 점수 | 키워드가 통계표명에 포함되는지 간단히 점수화 |
| 상위 결과 제목 비교 | `top_results.title`에 키워드 핵심어가 포함되는지 확인 |

## 11. 로그에 남길 문장

아래 문장을 8.10 작업 로그에 넣으면 좋다.

> 100개 확장 키워드 검색 테스트 결과, 97개 키워드에서 KOSIS 검색 결과가 확인되었다. 다만 `exists: true`가 항상 높은 관련도를 의미하지는 않았고, 일부 키워드는 상위 검색 결과가 실제 의도와 다른 통계표로 잡혔다. 특히 `대학교 재학생 수`, `미분양주택`, `외식 물가`처럼 표현이 넓거나 KOSIS 공식 용어와 다른 키워드는 애매한 결과가 나타났다. 또한 `노년부양비`, `인터넷 이용률`은 검색 결과 없음이 아니라 JSON 파싱 에러로 판단불가 처리해야 한다.
