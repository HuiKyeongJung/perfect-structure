KOSIS 키워드 검색 코드 오류 정리
================================

1. 실행 상황
-----------
keyword_search.py를 실행했을 때 프로그램 자체는 실행되었지만,
모든 키워드 결과가 status="error", exists=false로 출력되었다.

예시 오류 메시지:
Expecting value: line 1 column 1 (char 0)


2. 오류 의미
-----------
이 오류는 Python의 json.loads()가 빈 응답이나 JSON이 아닌 응답을
JSON으로 해석하려고 할 때 발생한다.

즉, "검색 결과가 없다"는 뜻이 아니라,
"KOSIS에서 받은 응답을 JSON으로 읽지 못했다"는 뜻이다.


3. 가능한 원인
-------------
- API 요청 파라미터가 부족했을 수 있다.
- format=json 파라미터가 빠져서 JSON 응답이 오지 않았을 수 있다.
- API key가 제대로 읽히지 않았을 수 있다.
- API 주소가 정확하지 않거나, KOSIS가 오류 페이지를 반환했을 수 있다.
- KOSIS가 오류 메시지를 HTML, 빈 문자열, 일반 텍스트로 반환했을 수 있다.


4. 현재 가장 먼저 수정할 부분
----------------------------
build_search_url() 함수 안의 params에 아래 값을 추가한다.

"format": "json"

수정 전:

params = {
    "method": "getList",
    "apiKey": api_key,
    "searchNm": keyword,
    ...
}

수정 후:

params = {
    "method": "getList",
    "apiKey": api_key,
    "format": "json",
    "searchNm": keyword,
    ...
}


5. 에러 메시지 개선 방향
-----------------------
기존에는 JSON 파싱 실패 시 아래처럼 이해하기 어려운 메시지가 출력되었다.

Expecting value: line 1 column 1 (char 0)

이를 아래처럼 바꾸면 원인을 더 쉽게 확인할 수 있다.

- 응답이 비어 있는 경우:
  "KOSIS API 응답이 비어 있습니다."

- JSON이 아닌 응답이 온 경우:
  "KOSIS API 응답이 JSON 형식이 아닙니다. 응답 앞부분: ..."


6. 보안 관련 주의사항
--------------------
API key는 .env 파일에서만 읽어야 한다.

실제 API 요청 URL에는 KOSIS 규격상 apiKey 파라미터가 들어가지만,
출력 결과 JSON이나 sample_result.json에는 요청 URL을 저장하지 않는 것이 안전하다.

따라서 결과에는 search_url을 남기지 않는 방향으로 수정한다.


7. 정리
------
이번 오류는 코드 실행 자체가 실패한 것이 아니라,
KOSIS API 응답을 JSON으로 해석하는 단계에서 실패한 것이다.

우선 format=json을 추가하고,
응답이 비었는지 또는 JSON이 아닌지 확인할 수 있도록 fetch_json()의 에러 처리를 개선한다.
